# Al Madrasat Habiib El Mustwafaa — School Management System

A full, working school management system for the madrasa in Kigorofani: a modern public website
with a real photo slideshow, a student portal, and a teacher/admin portal — all backed by a real
database and real authentication.

- **Frontend:** Next.js 14 (App Router) + TypeScript + Tailwind CSS
- **Backend:** FastAPI + SQLAlchemy, designed for **Supabase Postgres**
- **Auth:** Real JWT authentication with bcrypt-hashed passwords (not a demo/mock login)

This rebuilds and extends the original React app you provided: same subjects, teachers, students,
and branding ("Al Madrasat Habiib El Mustwafaa — Kigorofani"), a modernized design, a real backend,
and several new features the original didn't have (attendance tracking, real messaging, assignment
submission/grading, and analytics/reports for teachers).

### New features added beyond the original app
- **Attendance tracking** — teachers mark daily attendance per class; students see their own summary.
- **Real messaging** — teachers and students can message each other directly (inbox/sent).
- **Assignments with submission & grading** — students submit work, teachers grade it.
- **Reports & Analytics** — real charts (attendance by class, subject averages, grade distribution)
  built from live data — the old app's "Inafanyiwa kazi" (under construction) pages are now fully working.
- **Role-based accounts** — admin / teacher / student, each with their own permissions.

## 2. Set up Supabase (the database)

1. Create a free project at [supabase.com](https://supabase.com).
2. In your project, go to **Settings → Database → Connection string** and copy the **URI**
   (use the "Session pooler" connection string — it works well with a normal Python app).
3. You'll paste this into `backend/.env` as `DATABASE_URL` in the next step.

You do **not** need to create any tables manually — the backend creates them automatically on
first run, and the seed script fills them with demo data.

---

## 3. Run the backend (FastAPI)

Requires **Python 3.11+**.

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# now edit .env and paste your Supabase DATABASE_URL, and set a real SECRET_KEY

python seed.py                  # creates tables + demo data (run once)
uvicorn app.main:app --reload --port 8000
```

The API is now running at `http://localhost:8000`. Check `http://localhost:8000/api/health`.

Interactive API docs (auto-generated by FastAPI) are at `http://localhost:8000/docs`.

## 4. Run the frontend (Next.js)

Requires **Node.js 18+**.

```bash
cd frontend
npm install

cp .env.local.example .env.local
# edit .env.local if your backend isn't running on http://localhost:8000

npm run dev
```

Visit `http://localhost:3000` — you'll see the public homepage with the photo slideshow. Log in
with one of the demo accounts above to see the student or teacher portal.

## 5. Deploying for real use

- **Backend:** any host that runs a Python web app (Render, Railway, Fly.io, a VPS, etc.) works —
  just set the same environment variables from `.env.example`. Point `DATABASE_URL` at your
  Supabase project from step 2.
- **Frontend:** deploy to Vercel, Netlify, or any Node host. Set `NEXT_PUBLIC_API_URL` to your
  deployed backend's URL (e.g. `https://your-api.onrender.com/api`).
- Update `FRONTEND_ORIGINS` in the backend's `.env` to your deployed frontend URL, so CORS allows it.
- Before going live: change `SECRET_KEY` to a long random string, and change/remove the demo accounts.

## 6. Project structure reference

**Backend** (`backend/app/`)
- `models/` — SQLAlchemy database tables (users, students, teachers, subjects, timetable, exams,
  grades, attendance, assignments, announcements, events, messages)
- `schemas/` — request/response validation (Pydantic)
- `api/routes/` — one file per resource (auth, students, teachers, subjects, timetable, exams,
  attendance, assignments, announcements, events, messages, dashboard)
- `core/security.py` — password hashing + JWT
- `seed.py` — demo data generator

**Frontend** (`frontend/`)
- `app/page.tsx` — public homepage (hero, slideshow, programs, teachers, events)
- `app/login`, `app/register` — auth pages
- `app/(student)/...` — student portal: dashboard, timetable, exams, assignments, attendance,
  announcements, events, teachers directory, profile
- `app/teacher/...` — teacher portal: dashboard, students, subjects, schedule, exams & grading,
  assignments & grading, attendance marking, announcements, messages, reports, analytics, profile
- `lib/api.ts` — typed fetch wrapper that attaches the JWT to every request
- `lib/auth-context.tsx` — React context providing the logged-in user everywhere

## 7. A note on scope

This is a complete, working full-stack application — every page you see is wired to a real API
endpoint and a real database, not placeholder data (aside from the public homepage's marketing
copy, which is static by design). A few things worth knowing if you plan to run this for the
actual madrasa:

- File uploads (e.g. photo profile pictures, submitted homework files) aren't implemented — the
  assignment "submission" is text-only. Wiring up Supabase Storage for real file uploads would be
  a natural next step.
- There's no automated test suite yet; the app was manually verified end-to-end (registration,
  login, dashboards, grading, attendance, messaging) during development.
- For a live production deployment, put the backend behind HTTPS and set a strong `SECRET_KEY`.
